# Memovix Design System

## Philosophy

Memovix is not an admin dashboard.

It is a premium AI SaaS platform.

The interface should communicate:

- Confidence
- Intelligence
- Simplicity
- Speed
- Precision

Every screen should feel carefully crafted.

Avoid visual noise.

Prefer clarity over decoration.

---

# Design Inspirations

Primary Inspirations

- Linear
- Cursor
- Vercel
- Notion

Secondary Inspirations

- GitHub
- Figma
- Stripe Dashboard

Do NOT copy these products.

Create a unique design language inspired by them.

---

# Design Principles

Every screen must satisfy:

- Excellent visual hierarchy
- Consistent spacing
- Clear typography
- Strong readability
- Minimal distractions
- Fast interaction
- High information density without feeling crowded

---

# Theme

Dark First

Light Mode later.

Dark mode should feel premium rather than simply black.

---

# Color Palette

Primary Background

Near black

Secondary Background

Slightly elevated surfaces

Accent Color

Blue

Success

Green

Warning

Amber

Danger

Red

Information

Cyan

Avoid excessive gradients.

Use gradients only to highlight AI-related features.

---

# Border Radius

Cards

Large rounded corners

Buttons

Medium rounded corners

Inputs

Medium rounded corners

Dialogs

Large rounded corners

Keep radius consistent throughout the application.

---

# Shadows

Use soft shadows.

Never use heavy drop shadows.

Prefer subtle depth.

---

# Typography

Use a clean sans-serif font.

Recommended:

Geist

Fallback:

Inter

Hierarchy

Display

Heading

Subheading

Body

Caption

Maintain consistent font weights.

Never use more than two font families.

---

# Icons

Use Lucide React.

Maintain consistent icon size.

Avoid mixing icon libraries.

---

# Buttons

Primary

Filled

Secondary

Outline

Ghost

Text

Danger

Loading State

Disabled State

Every button must support loading.

---

# Inputs

Every input should support:

Label

Placeholder

Validation

Helper Text

Error State

Disabled State

Loading State

---

# Cards

Cards are the primary layout building block.

Every card should have:

Title

Description (optional)

Actions

Content

Footer (optional)

Avoid oversized cards.

---

# Tables

Tables should support:

Sorting

Filtering

Pagination

Loading

Empty State

Responsive layout

Sticky header where appropriate.

---

# Dialogs

Dialogs should:

Focus the primary action.

Support keyboard navigation.

Close gracefully.

Avoid oversized modal windows.

---

# Navigation

Sidebar should contain:

Workspace

Projects

Memories

AI Search

Timeline

Files

Notifications

Settings

Profile

Navigation should always remain predictable.

---

# Forms

Forms should feel simple.

Group related fields.

Avoid long forms.

Use inline validation.

---

# Empty States

Every empty state should:

Explain what happened.

Suggest the next action.

Never leave blank screens.

---

# Loading States

Prefer skeleton loaders.

Avoid spinners whenever possible.

Loading should preserve page layout.

---

# Error States

Every error should include:

Clear explanation.

Retry button.

Helpful action.

Never expose technical errors to users.

---

# Charts

Use Recharts.

Keep charts simple.

Minimal grid lines.

Readable labels.

Never overload dashboards with charts.

---

# AI Components

AI features are the identity of Memovix.

They should feel different from normal UI.

Examples:

AI Search

AI Suggestions

Semantic Results

Streaming Responses

AI Answer Cards

These may use subtle gradients or glow effects.

No excessive animations.

---

# Animations

Animations should support usability.

Never animate for decoration.

Animations should feel fast and natural.

---

# Accessibility

Keyboard navigation

Visible focus states

Proper contrast

ARIA support

Responsive layouts

Accessible forms

---

# Responsive Design

Desktop First

Tablet

Mobile

Every screen must function correctly across all devices.

---

# Quality Standard

Every new component must look like it belongs to the same design system.

If a component does not match the design language, redesign it instead of forcing it into the application.
