# Goal

Build the Projects module for Memovix.

Users should be able to browse, search, filter and navigate through their projects.

This phase focuses on frontend architecture and API integration.

Project creation, editing and deletion dialogs are intentionally deferred.

---

# Scope

Build:

- Projects page
- Projects list
- Project cards
- Search
- Status filter
- Empty state
- Loading state
- Error state
- Responsive layout

Integrate with the backend.

---

# Data

Use the existing backend Project endpoints.

Use TanStack Query.

No mock data.

---

# User Experience

The Projects page should feel like a modern SaaS application.

Prioritize:

- clarity
- speed
- discoverability
- responsive design

---

# Architecture

Separate:

- Page
- Components
- Hooks
- Services
- Types
- Query Keys
- Constants

Keep API logic outside components.

---

# Future Ready

Design so future phases can add:

- Create Project
- Edit Project
- Delete Project
- Archive
- Pagination
- Sorting
- Client assignment
- Team members

without restructuring existing code.

---

# Out of Scope

Do NOT implement:

- Create Project dialog
- Edit Project
- Delete Project
- Archive
- Infinite scrolling
- Pagination
- Project details page

Only browsing and viewing.
